# 实验室器材点检：采集手册

固定俯视相机拍摄实验台。用户另给一份所需器材清单，系统判断清单上的器材是否齐全。正式训练照片由采集者自己拍。本文是可以照着做的步骤，不是实验结果。

五类器材：螺丝刀 `screwdriver`、钳子 `pliers`、线缆 `cable_bundle`、万用表 `multimeter`、锤子 `hammer`。每类三种状态：`present` / `absent` / `unknown`。判定标准见 `docs/annotation_guide.md`。

两条拍摄时就要记住的规则：

- 线缆只指独立收卷的一束。万用表的红黑表笔线属于万用表，不要为了「看起来有线」再放一束线，也不要把它当成线缆。
- 文件名只表示哪一次、哪一个布置、哪一张变体，不能出现类别名、`present`、`absent`、`missing` 等答案。

## 1. 相机怎么固定

1. 相机装在三脚架或固定支架上，镜头垂直朝下，对准台面中心。先用约 70 cm 的高度试拍，再只改高度，直到整块检查区域都在画面里，四周再留大约一成边。
2. 用胶带在地面标出三脚架三个脚的位置。这一组照片拍完之前不要挪脚架，也不要转云台。
3. 对焦到台面后锁定对焦（手动对焦，或自动对焦一次后关掉连续对焦）。成对的两张之间不要重新对焦。
4. 曝光尽量用手动并锁定。只拿走一件金属工具时，自动曝光可能突然变亮，这一对就废了。
5. 关掉自动旋转。画面保持横向，建议 4:3，分辨率不低于 1280×960，JPEG 最高质量。
6. 每个 session 开始先拍一张空台，确认画面和上一批对齐。空台可以进数据集（五类都是 `absent`，前提是检查区域完整可见）。不要把尺子、便利贴或写着答案的纸条留在正式照片里。

中途如果碰过三脚架：在拍摄日志里记下，这个 session 剩下的照片不要和碰之前的照片编成一对。严重错位的整组重拍。

## 2. ROI（检查区域）

1. 在台面上贴一圈不反光的胶带，围出检查区域。模型只该看这块区域里的器材。架子上、地面上、画面边缘以外的东西不算。
2. 胶带要完整出现在画面中。贴好后不要再移动。
3. 器材的主体在胶带内，才可能标 `present`。只有一角伸进来、认不出是哪一类，标 `unknown`，不要标 `present`。
4. 胶带某一侧已经出画时，出画那一侧「有没有某件器材」无法确认，对应类别标 `unknown`，原因写「检查区域出画」。不要因为「这张照片里没看见」就标 `absent`。
5. 采集日志里记一列「ROI 是否完整」。不完整的照片仍要保留，它们是 `unknown` 的正式来源，但不要把它们和「ROI 完整、确实没有这件器材」混成同一种缺失。

## 3. 试采：20 个布置 × 5 个变体

试采用来走通拍摄、命名、标注和划分，大约 100 张。20 个布置分成 4 个批次，每批 5 个布置。每个批次都要同时包含「齐全」和「缺失」，不要一个批次只拍缺的。

| 批次 session_id | 布置 | 主光照 | 垫板 |
| --- | --- | --- | --- |
| `pilotb01` | l001–l005 | 日光，偏暖 | 原木色 |
| `pilotb02` | l006–l010 | 顶灯，偏冷 | 浅灰 |
| `pilotb03` | l011–l015 | 侧光 | 深色 |
| `pilotb04` | l016–l020 | 偏暗，可再加一盏小灯 | 与前面不同的一种垫板 |

`session_id`、`layout_id`、`variant_id` 都不要包含下划线。场景组 id 会拼成 `<session>_<layout>`。

每个布置固定拍下面 5 张。相机不动。

| 变体 | 拍什么 | pair_group_id |
| --- | --- | --- |
| v01 | 五类都在检查区域内（齐全） | 与 v02 相同，例如 `pilotb01_l001_p01` |
| v02 | 从 v01 只拿走下表那一件 | 与 v01 相同 |
| v03 | 按下表「缺两件」摆放。相对齐全差了两件，不要和 v01 编成一对 | 留空 |
| v04 | 回到五类都在，但每件都换一个位置 | 留空。位置变了、状态没变，不能当成一对 |
| v05 | 遮挡、失焦或出画，见第 6 节 | 留空，除非相对另一张只改了一个类别的状态 |

一张图只能有一个 `pair_group_id`。不要把 v01、v02、v03 三张放进同一个 pair。若还想要「从缺一件再拿走一件」的第二对，请另拍两张新照片，不要复用已经入对的那张。

### 缺失怎么分配

「拿走一件」每种器材 4 次。「缺两件」的 10 种组合各用 2 次。这样不会出现「钳子总是缺、锤子总是在」。

| 布置 | v02 拿走的一件 | v03 缺的两件 |
| --- | --- | --- |
| l001 | 螺丝刀 | 螺丝刀、钳子 |
| l002 | 钳子 | 螺丝刀、线缆 |
| l003 | 线缆 | 螺丝刀、万用表 |
| l004 | 万用表 | 螺丝刀、锤子 |
| l005 | 锤子 | 钳子、线缆 |
| l006 | 螺丝刀 | 钳子、万用表 |
| l007 | 钳子 | 钳子、锤子 |
| l008 | 线缆 | 线缆、万用表 |
| l009 | 万用表 | 线缆、锤子 |
| l010 | 锤子 | 万用表、锤子 |
| l011 | 螺丝刀 | 螺丝刀、钳子 |
| l012 | 钳子 | 螺丝刀、线缆 |
| l013 | 线缆 | 螺丝刀、万用表 |
| l014 | 万用表 | 螺丝刀、锤子 |
| l015 | 锤子 | 钳子、线缆 |
| l016 | 螺丝刀 | 钳子、万用表 |
| l017 | 钳子 | 钳子、锤子 |
| l018 | 线缆 | 线缆、万用表 |
| l019 | 万用表 | 线缆、锤子 |
| l020 | 锤子 | 万用表、锤子 |

v03 的摆法：先按 v01 把五件放好，再拿走上表那两件。不要在 v02 的基础上接着拿，否则 v02 会被放进两对。

## 4. 成对拍摄

一对的定义：相机、对焦、曝光、垫板都不动，只拿走或只放入一件器材，两张图恰好一个类别的状态不同。

1. 拍 v01。手离开画面后再按快门。
2. 只拿走计划中的那一件，放进画面外的盒子。不要顺手挪动其他器材。
3. 拍 v02。
4. 两行标注填同一个 `pair_group_id`。其余变体留空。
5. 若发现还碰了第二件，删掉重拍，不要标成一对。

只改位置的 v04 状态和 v01 相同，差 0 个类别，填了 pair 会在校验里失败。

## 5. 困难负样本

目的是减少两类误判：把表笔线当成一束线缆；把别的金属工具当成钳子。试采至少各拍 8 张，并且干扰物也要出现在「目标器材仍然在」的照片里，避免模型学到「看见扳手 = 没有钳子」。

表笔线与线缆：

- 万用表放在检查区域内，红黑表笔自然展开，不要盘成一束。
- 至少 4 张：没有独立线缆。线缆标 `absent`（ROI 完整时），万用表标 `present`。`hard_negative_tags` 填 `probe_leads_vs_cable`。l002、l005、l012、l015 的 v03 正好缺线缆且万用表还在，优先用这几张。
- 至少 4 张：独立线缆和展开的表笔同时在。线缆标 `present`，标签同样写上。否则「有细线 = 没有线缆」会变成捷径。
- 表笔始终算万用表的一部分。拿走万用表时把表笔一起拿走。

钳子与其他金属工具：

- 准备扳手或活动扳手当干扰物。它不是五类之一，不要新增类别。
- 成对拍法：v01 钳子和扳手都在；v02 只拿走钳子，扳手不动。两张都标 `pliers_vs_metal_tool`。状态只差钳子。
- 另外留一些「没有钳子、也没有扳手」的普通缺失（l002 以外的布置已经覆盖），以及「有钳子、没有扳手」的普通正样本。四个「v02 拿走钳子」的布置（l002、l007、l012、l017）里只选两个加扳手，不要四个全加。

## 6. unknown 怎么拍

`unknown` 表示这张图无法确认，不是「我猜没有」。原因写进 `unknown_reason`，写法见标注手册。

轮换使用，不要 20 张都用手挡：

- l001、l009、l013、l017：用手挡住一件，挡住的那件标 `unknown`，没挡住的仍按看得见的标。
- l002、l010、l014、l018：用纸或盒子挡住一件。
- l003、l011、l015、l019：对焦到台面以外，或轻移相机造成该区域失焦。能认出来的类别不要跟着标 `unknown`。
- l005、l007、l020：把三脚架保持不动，让检查区域一侧出画。出画一侧的类别标 `unknown`。
- l004、l008、l012、l016：手或纸进入画面，但五类都仍然看得清。这 4 张全部按实际在/不在标注，不要出现 `unknown`。它们用来打断「画面里有手 = 缺了东西」。

再补两条，避免把手变成缺失的捷径：

- 手挡住 A 时，B 如果完整可见，B 仍是 `present` 或 `absent`，不要整张图都标 `unknown`。
- 空手入画、什么都没挡，按没有手的规则标。

v05 若和某一张只差一个类别（例如从齐全变成「锤子被挡住所以 unknown」），可以单独组成一对。不要和已经占用的 v01/v02 共用 pair id。

## 7. 光照、背景、批次

- 试采的 4 个批次已经覆盖暖日光、冷顶灯、侧光、偏暗。正式采集保持至少这 4 种，不要只在一种灯光下把数据补齐。
- 垫板至少换 3 种颜色。ROI 胶带保持同一套，否则检查区域的边界会变。
- 每个批次里，五类作为「唯一被拿走的那件」都要出现（上表每个批次 5 个布置，正好一轮）。
- 反光：金属钳口和锤头会反光。侧光批次保留这些反光，不要全部换成哑光角度。看不清到自己都无法判断时标 `unknown`，不要猜。
- 同一批次先拍齐全再拍缺失，或反过来，都可以。不要把「缺失」只留在最后一个、光线已经不同的批次。

## 8. 正式数据规模

试采通过标注复核和一次划分之后，再扩到正式规模：

- 布置：160–240 个。
- 照片：800–1200 张。沿用每个布置约 5 个变体即可落在这个区间。
- 批次：8–12 个，跨不同天或至少不同时段。沿用试采的缺失分配表循环，不要另起一套「只缺钳子」的表。
- 成对、困难负样本、`unknown`、以及「有手但仍然可判断」的对照，按试采的比例继续拍。困难负样本建议不少于总照片的 10%，`unknown` 建议不少于 10%。这是采集目标，不是已有数据的统计。

正式 session 用拍摄日期加批次，例如 `20261120b01`，不要用 `pilot` 前缀。试采和正式数据不要编进同一个 `scene_group_id`。

## 9. 文件怎么命名

```text
data/raw/<session>/<layout>/<variant>.jpg
```

例子：`data/raw/pilotb01/l001/v02.jpg`。

写入标注 CSV 的 `image_path` 是相对 `data/` 的路径：`raw/pilotb01/l001/v02.jpg`。使用正斜杠。

不要使用的名字：`missing_pliers.jpg`、`no_hammer_v02.jpg`、`complete.jpg`。答案只出现在标注表里。

## 10. 每次拍摄要记下的元数据

这些内容给人和后续统计用，不送给模型。不要写进 `question_zh`，不要写进文件名，也不要写在放进画面的纸条上。

拍摄日志建议单独存成 `data/raw/<session>/capture_log.csv`（转换脚本不读这个文件）：

| 列 | 内容 |
| --- | --- |
| session_id / layout_id / variant_id | 与目录名一致 |
| capture_time | 拍摄时间 |
| operator | 拍摄人 |
| camera_height_cm | 镜头到台面的高度 |
| tripod_moved | 相对上一张是否碰过三脚架 |
| lighting | 日光 / 顶灯 / 侧光 / 偏暗 |
| background | 垫板 |
| roi_fully_visible | 胶带是否完整在画面内 |
| physical_items | 这一张实际放了哪些器材，以及扳手等干扰物 |
| action_from_previous | 相对上一张拿走或放入了哪一件；没有就写「重摆」 |
| hard_negative | 若是困难负样本，写类型 |

标注表 `data/annotations/templates/annotation_template.csv` 是另一张表，一图一行，交给 `scripts/data_csv_to_jsonl.py`。光照、背景等可以摘要进 `condition_tags`（用 `|` 分隔），供划分后的统计使用，仍然不要写进提示词。推荐标签：

- 光照：`lighting_warm`、`lighting_cool`、`lighting_side`、`lighting_dim`、`lighting_mixed`
- 背景：`background_wood`、`background_gray`、`background_dark`
- 其他：`baseline`、`position_shift`、`occlusion`、`defocus`、`partial_frame`

困难负样本标签只用：`probe_leads_vs_cable`、`pliers_vs_metal_tool`。

## 11. 拍完之后的命令

在项目根目录执行：

```bash
cd /root/gpufree-data/qwen_vlm && source env/activate.sh
envs/qwen_vlm/bin/python scripts/data_csv_to_jsonl.py \
  --csv data/annotations/pilot.csv \
  --out data/annotations/pilot.jsonl \
  --source real_lab \
  --question-set default \
  --seed 0
envs/qwen_vlm/bin/python scripts/data_validate.py data/annotations/pilot.jsonl
envs/qwen_vlm/bin/python scripts/data_split.py \
  --input data/annotations/pilot.jsonl \
  --out data/splits/v1 \
  --seed 0
envs/qwen_vlm/bin/python scripts/data_stats.py --split-dir data/splits/v1
```

`--question-set test_only` 是测试专用问法，不要用来生成训练 JSONL。默认每张图展开 2 条 checklist；`--presence-per-image 1` 才会额外生成单件有无问题。清单组合从 `configs/data/question_templates.yaml` 抽取，每条 2–4 类。

`data/smoke/synthetic/` 是程序画的简笔，`source=synthetic_smoke`，只用来跑通上述命令。不要把它计数进正式数据，也不要把它的统计写进数据卡。
