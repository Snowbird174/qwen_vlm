## 2. 任务定义

画面来自固定俯视相机。问题给出所需器材清单后，判断清单是否齐全。类别和状态以冻结的 `contracts/categories.yaml` 为准：

| id | 中文 | 范围 |
| --- | --- | --- |
| screwdriver | 螺丝刀 | 不区分一字 / 十字 |
| pliers | 钳子 | 不区分钳子类型 |
| cable_bundle | 线缆 | 独立收卷的一束。万用表表笔线不算 |
| multimeter | 万用表 | 整件器材，不读数 |
| hammer | 锤子 |  |

状态：`present`（有足够证据确认在检查区域内）、`absent`（检查区域完整且确认没有）、`unknown`（遮挡、出画、失焦或无法辨认）。

清单结论由冻结规则从状态推出，不是本数据卡要填的模型指标：任一所需器材 `absent` → 不齐全；否则任一所需器材 `unknown` → 无法确认；否则齐全。不在清单上的类别不影响结论。

## 6. 已知风险

采集设计上要避免、入库后要再检查的偏差：

- 某一类总是缺，或只在某一种灯光下缺。
- 用手遮挡表示缺失，使「画面里有手」变成捷径。手册要求同时拍「有手但器材仍可判断」的对照。
- 把表笔线标成线缆。
- 检查区域出画时把看不见写成 `absent`。
- 文件名或画面里的纸条泄露答案。

上述各项在真实数据中的实际比例：待真实数据。

## 7. 不应当怎么用

- 不要把合成冒烟集的损失、准确率或张数写成实验结论。
- 不要按单张照片随机划分。成对图和同一布置的变体拆开就是泄漏。
- 不要把 `unknown_reason`、光照标签或 notes 拼进提示词。
