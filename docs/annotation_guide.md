# 标注手册

一图一行，填 `data/annotations/templates/annotation_template.csv`。转换脚本再为每张图生成若干条问题和清单，标注员不要自己拆问题。模型只看见图片和问题，看不见本表里的状态、原因、标签和 notes。

状态只允许三个词：`present`、`absent`、`unknown`。类别列名用英文 id：`screwdriver`、`pliers`、`cable_bundle`、`multimeter`、`hammer`。

## 1. 三状态怎么判

只看检查区域（台面上胶带围出的范围）里这一张照片的内容。不根据「实验通常会放什么」来补全。

| 状态 | 什么时候用 |
| --- | --- |
| present | 该类器材的主体在检查区域内，而且轮廓或关键部件足够确认就是这一类。轻微遮挡、倒扣、反光，只要仍能确认，都算 present。不数个数，两把螺丝刀仍是 present。 |
| absent | 检查区域完整、清晰，而且能确认该类没有出现。看不清的区域不能拿来证明「没有」。 |
| unknown | 遮挡、失焦、出画或和别的物体混淆，导致标注员自己也无法确认有还是没有。 |

优先级：能确认在 → `present`；区域完整且能确认不在 → `absent`；否则 → `unknown`。不要用 `unknown` 表示「大概没有」。

`absent` 比 `unknown` 更强，而且只在看得到的区域上成立。出画、被挡住、糊成一团，都不是 `absent`。

## 2. 边界例子

1. 万用表在台上，红黑表笔展开，旁边没有独立成束的线。万用表 `present`。检查区域完整时，线缆 `absent`。表笔线不算线缆。`hard_negative_tags` 写 `probe_leads_vs_cable`。
2. 独立的一束线（扎带、魔术贴或手卷都可以）在检查区域内，能看出是一束而不是表笔。线缆 `present`。
3. 只有一根短线，看不出是不是「独立收卷的一束」。线缆 `unknown`，原因写「只有散线，无法确认是不是一束线缆」。不要勉强标 present。
4. 钳子和扳手并排，钳口和转轴看得清。钳子 `present`。扳手不单独成类。
5. 只有扳手，没有钳子，检查区域完整。钳子 `absent`，并标 `pliers_vs_metal_tool`。
6. 手挡住锤头，只剩一段木柄，无法确定是锤子还是别的木柄工具。锤子 `unknown`，原因写「手遮住锤头，只剩木柄，无法确认」。
7. 手在画面里，但五类器材都没有被挡住，检查区域也完整。按实际在或不在标注，任何一类都不要因为「有手」改成 `unknown` 或 `absent`。
8. 锤子在检查区域内，锤头被纸挡住一半，木柄和剩余锤头仍能确认是锤子。锤子 `present`。
9. 三脚架没动，检查区域右侧出画，锤子本来放在右侧。锤子 `unknown`，原因写「检查区域右侧出画」。不要标 `absent`。左侧仍完整可见的螺丝刀，按看得见的标。
10. 检查区域完整、清晰，台上没有锤子。锤子 `absent`。
11. 整张照片失焦。能辨认的类别照常标 present 或 absent；辨认不了的标 `unknown`，原因写「失焦，无法辨认」。不要为了省事把五类全部标 unknown，除非五类都确实无法辨认。
12. 万用表倒扣或屏幕背对镜头，机身形状仍能确认。万用表 `present`。本任务不读数。
13. 钳子放在检查区域外的架子上，区域内没有。钳子 `absent`。区域外的器材不算。
14. 螺丝刀只露出手柄，金属杆在区域内，能确认是螺丝刀（不区分一字和十字）。`present`。若只剩一个无法归类的色块，标 `unknown`。

## 3. unknown_reason 怎么写

键必须正好是状态为 `unknown` 的类别，不能多，也不能少。没有 `unknown` 时留空或写 `{}`。

两种写法都可以：

```text
hammer=手遮住锤头，只剩木柄，无法确认
```

```text
hammer=手遮住锤头，只剩木柄，无法确认;multimeter=检查区域右侧出画
```

或 JSON：`{"hammer": "手遮住锤头，只剩木柄，无法确认"}`。多个原因用英文分号分隔，原因正文里不要再写分号。

原因用短句，写清是遮挡、出画、失焦，还是无法和相似物区分。不要写「没有」——那是 `absent`，不应出现在本列。

## 4. 标注表各列

| 列 | 怎么填 |
| --- | --- |
| session_id, layout_id, variant_id | 与目录名一致，不含下划线 |
| image_path | 相对 `data/` 的路径，如 `raw/pilotb01/l001/v01.jpg` |
| pair_group_id | 成对的两张填同一个 id；否则留空。不要填 `null` 以外的占位词，空着即可（`null` / `none` 也会当成空） |
| 五个状态列 | `present` / `absent` / `unknown` |
| unknown_reason | 见上一节 |
| condition_tags | 光照、背景、遮挡等，用 `\|` 分隔。见采集手册的推荐词表 |
| hard_negative_tags | 没有就留空。只用 `probe_leads_vs_cable` 或 `pliers_vs_metal_tool` |
| annotation_verified | 复核通过后填 `true`，否则 `false`。不要留空 |
| notes | 给人看的话。争议写「争议：……」。这一列不会进入 JSONL |

同一张图的五行状态在所有生成样本里必须一致。不要为不同问题填不同状态。

## 5. 复核

标注完成先自查，再交复核。复核范围：

1. 全部含 `unknown` 的照片，逐张复核。
2. 全部困难负样本（两个 hard_negative 标签），以及 notes 里写了「争议」的负样本。普通的「确实没有」可以不进这一档。
3. 其余普通照片：每个 session 随机抽查，数量取「10 张」和「该 session 的 10%」里较多的那个。抽到的清单写在该 session 的复核记录里。
4. 复核人不要只看自己刚标完的那一批。试采至少换一位同学看上述范围。

复核时改了状态或原因：把该行 `annotation_verified` 改为 `true`，在 notes 里追加一句改动，并在下方修订记录加一行。没复核的行保持 `false`，不要提前改成 `true`。

有手的对照张（手在画面里但器材仍可判断）纳入第 3 类随机抽查，不必因为有手就全部双人复核。目的是确认没有人把「有手」标成缺失。

## 6. 修订记录

标注指南本身的修改，和某一张照片的标签修改，都用这张表。照片改动再抄一行进该照片的 notes。

| 日期 | 修订人 | 范围 | 变更 | 原因 |
| --- | --- | --- | --- | --- |
| 2026-11-16 | 初稿 | 全手册 | 建立三状态、unknown_reason 和复核范围 | 采集开始前的判定约定 |

照片改动的「范围」写 `session/layout/variant`，「变更」写清旧值和新值。例如：

| 日期 | 修订人 | 范围 | 变更 | 原因 |
| --- | --- | --- | --- | --- |
| 2026-11-20 | （复核人姓名） | pilotb01/l003/v05 | hammer: absent → unknown | 锤头出画，不能当作缺失 |

notes 里的对应句子：

```text
rev1 2026-11-20 复核人: hammer absent→unknown，锤头出画
```

不要只在表里改状态、不留记录。改完后重新跑 `scripts/data_validate.py`，确认 `unknown_reason` 的键和 `unknown` 类别一致。
